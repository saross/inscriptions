### Phase 2 — H2 mixture-model refinements (surfaced 2026-06-02; see Decision 33 + recovery-grid utility review)

All five are **deferred** (none blocks the current draft; the model is usable with stated caveats). The first two are the fit-side improvements Shawn asked to log on 2026-06-02; items three and four were surfaced by the 2026-06-02 Q&A on subset-scale use; the fifth (flat-null divergences) was surfaced by the 2026-06-03 cross-grid adjudication.

- [ ] **Informed α prior from the empirical-Bayes cohort.** Replace the flat `Beta(1,1)` α prior with one anchored to the Stage-1/Stage-2 calibration cohort, to reduce the residual α/shape-complexity ridge bias (operating-envelope 90th-pct |bias| ≈ 0.18). **Why**: would let α be reported more precisely (potentially re-admit it as a gated quantity). **Cost/caveat**: a model change → full recovery-grid re-run (~30–60 h sapphire); risk of prior-pull (2026-05-24 F1 deliberately kept `Beta(1,1)` for that reason). **Revisit**: only if a tight α gate or precise α claims are later required.
- [ ] **Roughness-tolerant `p_gen` prior.** Add a component (e.g. heavier-tailed GRW innovations, or a horseshoe-type term) so the genuine-SPA prior can represent sharp features (regnal spikes). **Why**: the band-calibration diagnostic (2026-06-02; `runs/2026-06-02-recovery-utility-check/`) showed the p_gen credible band is overconfident for sharply-peaked signals and degrades at large N (regnal_cluster pointwise 95 % coverage 0.23 at N=50 000); the smoothness prior cannot represent the real corpus's regnal clustering (AD ~77/122/212). **Cost/caveat**: model change → grid re-run; risk of over-fitting noise into spurious peaks. **Revisit**: before any paper claim that leans on peaked-region credible bands.
- [ ] **Extend the recovery grid downward in N (subset-scale characterisation).** The grid validates only N ∈ {2 000, 10 000, 50 000} — empire / large-province scale, which **matches where the mixture is actually fitted**: per the prereg (§"Scope of the mixture correction"), per-city mixture fits were *deliberately not pursued* (unidentified for ~600 of ~815 cities, N < 100); subset work instead uses date-window-filtered counts (H3a/H3c) and the §5 hierarchical aoristic model (validated to N\*≈300). So this item is **not** about re-introducing per-subset deconvolution. It is worth doing to (a) characterise the deconvolution's small-N behaviour for the reachability story, and (b) validate **H3b's application of the empire-estimated convention correction to subset SPAs** (which the prereg does scan on subsets, conditional on Phase-1 reachability). Add low-N cells (e.g. N ∈ {100, 250, 500, 1 000}). **Cost**: partial grid re-run. **Revisit**: with H3b, or if per-subset deconvolution is ever reconsidered. **Cross-ref**: reachability-guide tertiary items; Phase-1 reachability thresholds.
- [ ] **Calibration-cohort post-stratification reweighting by inscription type.** The narrow-dated calibration cohort (which informs the `p_gen` prior) is strongly type-skewed vs the corpus: epitaphs 39.3 % of corpus but 9.0 % of narrow-dated (0.23×); honorific 5.5 %→17.4 % (3.15×); building/dedicatory 4.6 %→12.7 % (2.73×) (verified 2026-06-02 on `type_of_inscription_clean`). So the empirical `p_gen` prior may reflect the temporal pattern of precisely-dated *public/official* types, not the corpus. Reweight the cohort to the corpus type composition (or report sensitivity to it); add a type-stratified validation. **Why**: representativeness of the calibration cohort. **Revisit**: before production fits whose `p_gen` prior must be corpus-representative. **Cross-ref**: 2026-05-24 type-bias finding; post-stratification-reweighting design.
- [x] **Resolve the flat-null sampling divergences (residual after F3).** **RESOLVED 2026-06-04 — option (b): the divergences are benign, so the gate was relaxed (not the model).** A prior-art scout (Stan/Betancourt: investigate divergences, don't auto-reject; no field rate-threshold) + a direct re-score of the stored per-replicate data established the flat-null divergences are benign (in-envelope: 10.2 % of reps diverge, median 1, max rate 0.36 %; diverging reps recover *no worse* — Mann–Whitney p ≈ 0.36; all pass R̂/ESS). The convergence gate was changed from zero-tolerance to R̂/ESS + a benign-divergence check (encoded in OSF Amendment 01 §A5.5.1, 2026-06-04); Grid A re-scores to B = A = 98.6 %; no re-fit needed. Grounding: `planning/martin-review-statistical-grounds-2026-06-04.md`. *Original analysis:* Under a *flat* genuine SPA, 24/60 in-envelope `flat_baseline` cells fail the convergence precondition (`convergence_pass_rate < 0.90`) because a small fraction of replicates hit ≥1 divergence and the gate is zero-tolerance (`n_divergences == 0`, fit.py:103-107). The divergence *rate* is tiny (≈0.002–0.009 % of draws; 12–74 per ~800 k) and recovery is unaffected (all 24 recover flatness, W1 ≤ 10), but it pushes the flat null below the convergence bar. **The standard non-centred-GRW fix is already in place (F3, `cell_lib.py:345-358`, adopted 2026-05-24) and does NOT eliminate it** — the residual is most likely the `sigma_smooth → 0` degeneracy under no-signal truth (when the genuine SPA is flat, `sigma_smooth` collapses toward 0 and the increments `z_pgen` become near-unidentified). **Why it matters**: it is the *sole* driver of the corrected-criterion A-vs-B gap on Grid A — 98.5 % (eligible-in-envelope) vs 91.9 % (all-in-envelope, non-converged = fail); see Decision 33 / §A5.5.1 and the 2026-06-03 adjudication. Settling it would make the flat null converge cleanly and collapse the two numbers. **Candidate fixes to test (small diagnostic re-fit on a few flat cells, NOT the full grid, ~minutes)**: (a) a `sigma_smooth` lower-bound / reparam for the near-zero regime; (b) relax the zero-tolerance divergence gate to allow a tiny divergent fraction (a *criterion* change, per Bayesian-workflow norms — Talts 2018 / Modrák 2025) rather than a model change; (c) confirm the funnel mechanism by inspecting `sigma_smooth` posteriors on a few flat replicates first. **Cost**: minutes (handful of flat-cell re-fits), not the full grid. **Revisit**: when settling the headline corrected-criterion figure, or before the methods-paper convergence/limitations discussion. **Cross-ref**: Decision 33 convergence precondition; `fit.py:103-107`; `cell_lib.py:345-358`; 2026-06-03 cross-grid adjudication.

## Failure modes — avoid (cumulative across the project)

- **Path typos in agent briefs.** Sapphire workdir is `~/Code/inscriptions`.
- **`pgrep -f` self-match.** Use bracket-escape: `pgrep -f "[.]venv/bin/python3.*foo.py"`.
- **Agent stalling on inline script streaming.** Long Python / R scripts via Write tool's `content` parameter; never stream as chat (600 s watchdog).
- **Monitor loops on stale files.** Use mtime or fresh-run markers, not file existence.
- **Zotero FTS does not index DOI field.** Use locally-built DOI index for idempotency.
- **Agent silent-parameter-reduction** (critical-friend gate failure pattern). Hard-stop rules in briefs.
- **Background-agent monitor-and-exit pattern.** Agents that arm a Monitor and exit don't re-fire from monitor events. Use Bash run_in_background with `until ! kill -0 PID` for "wait for PID death" patterns.
- **baorista API gotchas** (preserved from smoke-test iterations 2026-05-03):
  - `timeRange` must be descending (LARGER first).
  - `(upper - lower + 1) %% resolution == 0` required.
  - Per-event col1 > col2 (numeric ordering, NAMES are conventional).
  - Every event must satisfy `lower <= col2 <= col1 <= upper`.
  - `expfit` returns S3 `fittedExp` with `$rhat` / `$ess` directly — no `$samples` slot.
- **Sapphire fresh-R-install user-library bootstrap** (preserved from baorista install fix 2026-05-04): without `R_LIBS_USER` directory creation + `.libPaths()` push, `install.packages()` falls back to root-owned `/usr/local/lib/R/site-library` and crashes within seconds.
